These are the checklist's "Kobo pilot minimum set", ready to paste into the pilot form. They follow RT's decisions:

- RT runs the project personally, with a documented path to hand it to an organization later.
- Contributors must be 18+.
- Data is licensed CC BY 4.0.
- No targeted outreach to the UK or EU at launch.
- No ads, and the data is never sold.

> **Before use:**
> 1. Fill in the `[placeholders]`.
> 2. Have a fluent Nepali speaker check the Nepali text, and read it aloud to one elder to test clarity.
> 3. Have a lawyer review it before the *public* launch; for the pilot this is optional.

[PROJECT] is a volunteer project collecting the names of everyday things in Magar Dhut, Kham and Kaike. It is run personally by [OPERATOR]. Contact: [EMAIL]. This is a pilot (test).

- your district

## Part 5 — Pilot questions (end of form)

These test the assumptions the pilot exists for. Use multiple choice where possible.

1. प्रश्न ("तपाईंको भाषामा यसलाई के भनिन्छ?") बुझ्न सजिलो थियो? / Was the question easy to understand? (Yes / Somewhat / No)
2. देवनागरीमा टाइप गर्न सक्नुभयो? / Could you type in Devanagari? (Yes, easily / With difficulty / No, I used Roman letters)
3. कुन किबोर्ड प्रयोग गर्नुभयो? / Which keyboard did you use? (Gboard Nepali / other Nepali keyboard / English keyboard / don't know)
4. तपाईंको भाषामा नेपालीमा नभएका आवाज छन्? कसरी लेख्नुभयो? / Does your language have sounds Nepali letters can't write? How did you write them? (free text; this is the key question for Kham)
5. शब्द बोलेर रेकर्ड गर्न मन पराउनुहुन्थ्यो? / Would you rather record the word by voice? (Yes / No / Both)
6. कति समय लाग्यो? / About how long did it take? (<10 min / 10–20 / >20)
7. कुनै चित्र अस्पष्ट थियो? / Was any picture unclear? (free text)
8. अरू केही सुझाव? / Any other suggestions? (free text)

## Part 6 — Handover protocol (operator's internal document)

This is the "proper documentation" for a future handover. **Set up the transferable pieces now**; they cost nothing today and are painful to retrofit.

**Set up now [I]:**

- **A project email address** (e.g. a new Gmail or Proton account, or an address on the project domain). Use it for every service. Don't use RT's personal address.
- **The domain** registered with the project email.
- **A GitHub organization**, not a personal account, holding the app and data repos. Transferring an organization is a one-step handover.
- **Hosting (Cloudflare)** and the pilot tool account registered with the project email.
- **A shared password-manager vault** for all credentials, plus 2FA recovery codes stored in it.
- **A second trusted admin** with access to the vault, to protect against losing everything if RT becomes unavailable.

**Handover dossier.** Keep it current; it lives in the private repo `docs/handover/`:

1. An inventory of accounts, domains, repos, storage buckets, backups and who holds which credentials.
2. A data dictionary: every table and field, what it means, and its retention rule.
3. **Every consent version ever used**, plus a mapping from each contribution to the consent version it was given under.
4. A log of deletion and correction requests: request date, action, completion date. No personal data beyond the code word.
5. A dataset release history (versions, DOIs, what changed) and the deposit locations (Zenodo, ELAR).
6. Image licence records.
7. A runbook: deploy, back up, restore, export, and respond to a report or a breach.
8. The community agreements (advisory group, Local Contexts labels).

**Conditions any receiving organization must accept in writing:**

- Keep the same commitments: no sale of data, no advertising using contributor data, CC BY 4.0 for the dataset, and the same contributor rights.
- Honour all outstanding deletion requests, and the withdrawal policy.
- Keep the community advisory arrangement, or replace it with a more representative one.
